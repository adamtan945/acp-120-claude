Component 與預設指派

  1. Component只在 CMP；依功能、部門或工作流分組；project admin 建立。
  2. Component 的 default assigneeProject default、Component lead、Project lead、Unassigned。
  3. 多個 component先比類型：Component lead ＞ Project lead ＞ Unassigned ＞ Project default；多個 component 都是 Component lead 時，依 component 名稱字母序（不是 lead 的名字）。
  4. 沒有 component用 project 的 default assignee（Unassigned 或 project lead）。
  5. 被指派的人要 Assignable User沒有就跳過。
  6. Unassigned 選不到全站的 Allow unassigned issues 關閉時。
資料來源（5）有疑慮時點開看官方原文
  • What are Jira components?Jira components are only available in company-managed spaces, and are scoped to the space they’re created in.
  • How to Manage Components and Default Assignees in Jira Software Projects (KB)Components are assigned in the order: Component Lead >> Project Lead >> Unassigned >> Project default.
  • How to Manage Components and Default Assignees in Jira Software Projects (KB)To determine an assignee of an issue with multiple components that have leads, Jira considers the name of the component, not the name of the lead.
  • How to Manage Components and Default Assignees in Jira Software Projects (KB)If no, then Jira assigns the issue to the default assignee at the project level, which is either Unassigned or Project Lead.
  • How to Manage Components and Default Assignees in Jira Software Projects (KB)If the Component Lead doesn’t have the Assignable user project permission, they won’t be assigned to an issue where their Component is set.

設定

設定 component 與 project default

  1. ComponentProject settings → Components → Create component：名稱、description、component lead、default assignee。
  2. Project defaultProject settings → Details → Default assignee（Unassigned 或 Project lead）。
  3. Allow unassigned全站設定 Allow unassigned issues 關閉時，project default 不能選 Unassigned。
本段必考
  • Component lead 也要有 Assignable User。

動手做

實作 Lab：四個 component 搶指派：誰拿到 issue

約 25 分鐘Project admin（component、Details）；Jira admin（試試看 T3 的全站設定）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：建四個 default assignee 類型不同的 component，用 Automatic 建 issue，驗證多個 component 時的優先順序。

這個 Lab 對應的考點

Automatic 指派：手動選的人 ＞ component 的 default assignee ＞ project default。多個 component 先比類型（Component lead ＞ Project lead ＞ Unassigned ＞ Project default），都是 Component lead 時依 component 名稱字母序；lead 沒有 Assignable User 會被跳過。Project default 只能 Unassigned 或 project lead。

準備

  • 你是 WEB 的 Space owner（project lead）；Leo 在 Developers，有 Assignable User；Kim 在 Users，沒有 Assignable User（120.1.4 的狀態）。
  • 全站的 Allow unassigned work items 是開啟的（⚙ Settings → System → General configuration 可確認）。

步驟

  1. 你應該看到：Project default assignee＝你。
  2. 你應該看到：清單列出四個 component 與各自的 lead、default assignee（現行畫面可能把 lead 叫 owner）。
  3. 你應該看到：指派給 Leo：只有一個 component，用它的 default assignee。
  4. 你應該看到：指派給你：沒有 component，用 project default assignee。
  5. 你應該看到：Leo：Component lead 類型最高，蓋過 Project default。
  6. 你應該看到：Unassigned：Unassigned 高於 Project default；不會先把 Project default 展開成你。
  7. 你應該看到：Leo：同類型時依 component 名稱字母序，API 排在 Web 前面。
  8. 你應該看到：你：建立時手動選的人永遠優先，component 設定不管用。

試試看：改一個設定，觀察差異

T1把 API 的 lead 改成你、Web 的 lead 改成 Leo，再建一張 API＋Web 的 Bug。看結果
指派給你：看的是 component 名稱（API 在前），不是 lead 的名字。
T2把 Docs 的 lead 設成 Kim（沒有 Assignable User）、default assignee 改成 Component lead，建一張 Docs＋Misc 的 Bug。看結果
Kim 不會被指派（沒有 Assignable User 就被跳過），Jira 改用下一個順位；這裡通常落到 Misc 的 Project default，也就是你。如果畫面不讓你把 Kim 設成 lead，也是同一個原因。
T3⚙ Settings›System›General configuration → Edit settings：關掉 Allow unassigned work items，再回 WEB 的 Details 看 Default assignee。看結果
通常選不到 Unassigned 了。這是全站設定，看完立刻改回開啟。
