3 分鐘速覽

Status、transition 與它的零件

  1. Status 是全站物件有 category：To Do、In Progress、Done（決定顏色與報表）。
  2. Transition兩個 status 之間的路；可掛 screen、properties、conditions、validators、post functions。
  3. Condition → validator → post functionCondition 決定按鈕出不出現；validator 在提交時檢查；post function 在通過後自動做事。
  4. Resolution 很重要有 resolution＝已解決；用 transition screen 或 post function（Update issue field）設定，reopen 時清空。
  5. Board 與 statusBoard 欄位對應 status；workflow 加了新 status 卻沒 map 到欄位，issue 會從 board 消失。
  6. Custom event在 post function 觸發自訂 event，notification scheme 再依 event 寄信。
零件

Transition 的三個階段

需求用什麼
只有 QA role 能把 issue 轉到 DoneCondition：User Is In Project Role
轉 Done 前 Fix version 必填Validator：Field Required（或 transition screen＋required）
所有 sub-task 完成才能關 parentCondition：Sub-task Blocking Condition
轉 Done 時自動設 resolution＝DonePost function：Update Issue Field（或 transition screen）
Reopen 時清空 resolutionPost function：Update Issue Field → Resolution = None
轉換時寄特別通知Post function：Fire event（custom event）＋notification scheme

  • Condition 藏按鈕；validator 擋提交；post function 事後做。
Resolution

為什麼重要、怎麼設

  • Jira 用 resolution 有沒有值判斷 issue 是否「已解決」：filter 的 resolution = Unresolved、報表、dashboard gadget 都看它，不看 status 名稱。
  • 設定方式：Done 的 transition 掛含 Resolution 欄位的 transition screen；或用 post function 自動設值。
  • Reopen（從 Done 回到 To Do／In Progress）時要用 post function 把 resolution 清空，否則 issue 會「在進行中卻顯示已解決」。
  • 不要把 Resolution 放在 create／edit screen，否則一建立就被當成已解決。
考題長相

「Issue 在 In Progress，卻沒出現在 resolution = Unresolved 的 filter」→ reopen transition 沒清 resolution。加 post function：Update Issue Field → Resolution → None。

本段必考
  • Resolution 有值＝已解決。
  • Reopen 要清 resolution。

設定用途
Workflow properties在 status 或 transition 加 key／value，例如 jira.issue.editable=false（該 status 不能編輯）、jira.permission.* 細部限制

編輯 workflowJira admin 編輯；已發布的 workflow 以 draft 修改後 publish；換 workflow scheme 時要對應舊 status
