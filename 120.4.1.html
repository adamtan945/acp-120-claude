3 分鐘速覽

Status、transition 與它的零件

  1. Status 是全站物件有 category：To Do、In Progress、Done（決定顏色與報表）。
  2. Transition兩個 status 之間的路；可掛 screen、properties、conditions、validators、post functions。
  3. Condition → validator → post functionCondition 決定按鈕出不出現；validator 在提交時檢查；post function 在通過後自動做事。
  4. Resolution 很重要有 resolution＝已解決；用 transition screen 或 post function（Update issue field）設定，reopen 時清空。
  5. Board 與 statusBoard 欄位對應 status；workflow 加了新 status 卻沒 map 到欄位，issue 會從 board 消失。
  6. Custom event在 post function 觸發自訂 event，notification scheme 再依 event 寄信。

Resolution

為什麼重要、怎麼設

  • Jira 用 resolution 有沒有值判斷 issue 是否「已解決」：filter 的 resolution = Unresolved、報表、dashboard gadget 都看它，不看 status 名稱。
  • 設定方式：Done 的 transition 掛含 Resolution 欄位的 transition screen；或用 post function 自動設值。
  • Reopen（從 Done 回到 To Do／In Progress）時要用 post function 把 resolution 清空，否則 issue 會「在進行中卻顯示已解決」。
  • 不要把 Resolution 放在 create／edit screen，否則一建立就被當成已解決。
考題長相

「Issue 在 In Progress，卻沒出現在 resolution = Unresolved 的 filter」→ reopen transition 沒清 resolution。加 post function：Update Issue Field → Resolution → None。

本段必考
  • Resolution 有值＝已解決。
  • Reopen 要清 resolution。

動手做

實作 Lab：在 WEB 的 workflow 加 condition、validator、post function

約 30 分鐘Jira admin

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在同一個 transition 先後加限制、驗證與自動動作，用 Leo 的視角比較差別；再驗證 resolution、status 屬性與 board 欄位的關係。

這個 Lab 對應的考點

Condition 決定按鈕出不出現；validator 在提交時檢查；post function 在轉換後自動做事。Resolution 有值＝已解決，reopen 要清空。新 status 要 map 到 board 欄位；jira.issue.editable=false 讓 status 不能編輯；custom event 要由 post function 觸發。

準備

  • WEB 有 v2.0（120.2.3 留下的）；有一張在 To Do、沒有 Fix version 的 Story，assignee 是 Leo。
  • 改的是 WEB 用的 workflow；如果它被其他 space 共用，會一起變。

步驟

  1. 你應該看到：Status 依 category（To Do、In Progress、Done）分色；點 transition 會打開 details，Rules 分成 Restrict transitions、Request input、Validate details、Perform action 四類。
  2. 你應該看到：Leo 的 status 選單沒有 Done（路直接不出現）；你看得到。Condition 是事前把路藏起來。
  3. 你應該看到：Leo 看得到 Done，但按下後被擋並顯示錯誤；設好 Fix version v2.0 再轉就過。Validator 是提交時才檢查。
  4. 你應該看到：剛轉 Done 的 Story 通常不在結果裡（Done 時 resolution 被設了值）。Jira 看的是 resolution，不是 status 名稱。
  5. 你應該看到：如果它沒出現：這就是 reopen 沒清 resolution 的考題情境，status 在進行中卻被當成已解決。如果出現了：表示這個 workflow 已經會清 resolution，去 transition 的 Rules 找找是哪一條。
  6. 你應該看到：轉回 In Progress 後 resolution 被清空，Story 回到 Unresolved 清單。
  7. 你應該看到：欄位都不能編輯了：status 屬性可以在 permission scheme 之外再鎖一層。
  8. 你應該看到：那張 issue 從 board 與 backlog 消失。Board settings›Columns：Lab QA 在 Unmapped statuses；拖到一個欄位後，issue 回來了。

試試看：改一個設定，觀察差異

T1⚙ Settings›System›Events（在 Advanced 區）→ 頁面最下方 Add New Event：名稱 Lab QA Ready，選一個 template → Add。再到 workflow 選進入 Lab QA 的 transition，在 EVENT 下拉選單選它 → Update workflow。回 Events 頁看狀態。看結果
剛建立時是 Inactive；被 transition 用上之後變 Active。要真的寄信，還得在 notification scheme 設這個 event 的收件人。
T2在進入 Done 的 transition 加 Subtask Blocking Condition，選 Done。把一張有未完成 sub-task 的 Story 轉 Done。看結果
轉不過去：所有 sub-task 完成前，parent 不能進 Done。
T3（想像，不實際做）把 Resolution 欄位放進 Create 與 Edit screen。看結果
Issue 一建立就有 resolution，被當成已解決，所有 Unresolved 的 filter 都漏掉它。Resolution 只在 transition screen 或 post function 設定。
心像錨點：閉上眼睛想一次這個畫面

Workflow editor 右邊的 transition 面板，Rules 四格：Restrict、Request input、Validate、Perform action。條件藏、驗證擋、後置做；回頭要清 resolution。

收尾

  • 移除 Done transition 上的 Fix versions 必填與 Subtask Blocking Condition，以及 Done status 的 jira.issue.editable。
  • 把 Lab QA 裡的 issue 移回原 status，從 board 欄位移除並刪掉 Lab QA；transition 的 EVENT 改回原本，再刪除 Lab QA Ready（只有 Inactive 的 custom event 能刪）。
  • In Progress transition 的清 resolution 可以保留（這是正確的設定）。
