Backup、restore 與匯入

  1. Backup managerSettings → System → Backup manager → Create backup for cloud；可勾附件、avatar、logo。
  2. 頻率含附件時兩次 backup 至少間隔 48 小時。
  3. 包含Issue 與欄位、board／sprint、使用者與 group、留言、設定（workflow、scheme、screen…）、archived projects。
  4. 不包含Automation rules（要另外匯出）、第三方 app 資料、Opsgenie 功能、Assets、app access 設定。
  5. 誰能做建立 backup：Jira admin 或 org admin；匯入 backup（覆蓋整站）：org admin（官方 Learning 課程）。
  6. Restore（匯入 backup）會覆蓋站上所有資料；Atlassian Backup & Restore 只能還原到沒有資料的 app、30 天內的 backup。
  7. 其他匯入CSV／JSON 匯入到新的或現有 project（CSV 有 Work Item Key 時會更新既有 issue）；Trello 每個 board 建一個新的 TMP（需 org admin）。
資料來源（5）有疑慮時點開看官方原文
  • Export data from Jira CloudYou can backup your Jira data at any time. However, if you include attachments, avatars, and/or logos, you'll need to allow 48 hours between backups.
  • Export data from Jira CloudAlthough automation flows aren’t automatically exported, you can manually export and import automation flows.
  • Restore data using system backup and import in JiraJira admins can only create backup files. Org admins can create backup files and import backup files.
  • Restore app data from backupYou can only restore backups to apps that are empty and contain no user-generated data.
  • Import data from TrelloThe import process will create a team-managed space for each of your boards.
Backup

建立與內容

項目說明
誰建立 backup：Jira admin（Administer Jira）或 org admin；匯入 backup：org admin（org admin 用 Jira 設定時仍需 Jira app admin 存取）；org admin 可以封鎖匯出
位置Settings → System → Import and export → Backup manager
附件勾選後包含附件、avatar、logo；含附件時 48 小時一次
包含Issues、fields、boards、sprints、users、groups、comments、configuration、Advanced Roadmaps、archived projects（官方 Learning 課程列為 archived spaces）
不包含Automation rules、Marketplace app 資料、Opsgenie 功能、Assets、app access（Assets：support 文件列為不能匯出，但 Learning 課程寫包含 JSM assets data，兩處官方說法不同）

Restore 與匯入

覆蓋 vs 新增

方式效果適合
匯入 Jira Cloud backup（site import，org admin）覆蓋站上所有資料與設定；archived projects 包含在 backup 中（還原後是否維持封存狀態官方未明說；Server 匯入 Cloud 有變回未封存的已知問題 CLOUD-11391）整站還原、搬站
Atlassian Backup & Restore（org admin＋app admin）Premium／Enterprise 付費 add-on；可排程；還原 30 天內的 backup 到沒有資料的 app；app access 要另外核准災難復原
CSV／JSON importer匯入到新的或現有 project；可對應欄位；CSV 有 Work Item Key 時更新既有 issue；不覆蓋整站（CSV：Jira admin）從其他工具搬資料
Trello importer每個 board 建成一個新的 team-managed project（需 org admin）從 Trello 轉換
Jira Cloud Migration Assistant加入資料、不覆蓋；不搬的例子：global permissions、general configuration（時區、語言）、mail handlers、issue collectors、system dashboardServer／DC 到 Cloud
還原前

匯入完整 backup 會覆蓋所有現有資料。先做目前站台的 backup；調整 backup 檔只能選擇要不要匯入資料庫、附件、avatar、logo，不能只匯入特定 project（官方 KB）；要加入部分 project 的資料請用 CSV／JSON。

本段必考
  • Site import＝覆蓋；CSV／JSON＝新增。
資料來源（5）有疑慮時點開看官方原文

  • Overview of Atlassian Backup and RestoreYou need to have organization admin and app admin permissions to back up and restore data.
  • Restore app data from backupYou can only restore backups to apps that are empty and contain no user-generated data.
  • Import data from a CSV fileTo update existing work items, your CSV file needs to contain a column that maps to Work Item Key.
  • What gets migrated with the Jira Cloud Migration AssistantThe Jira Cloud Migration assistant adds data to a Jira Cloud site without overwriting any existing data.

動手做

實作 Lab：建一份 backup，看還原的入口但不按

約 25 分鐘建立 backup：Jira admin；匯入或還原整站：org admin（Atlassian Backup & Restore 另需 Premium／Enterprise 的付費 add-on）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：親手建立不含附件與含附件的 cloud backup、打開 zip 看結構；還原、匯入整站只看畫面與條件，不執行。

這個 Lab 對應的考點

Backup manager 建 backup，含附件時兩次至少隔 48 小時；automation rules、第三方 app 資料不在 backup 裡；匯入 backup 會覆蓋整站；Atlassian Backup & Restore 只能還原到沒有資料的 app、30 天內的 backup。

準備

  • 只看不做：本 Lab 的匯入、還原步驟只到看畫面為止。真的要練還原，只能在一個可以整個丟掉的站台做，因為匯入 backup 會覆蓋那個站的所有資料。
  • WEB 有幾張帶附件的 issue（任意小圖即可）。

步驟

  1. 你應該看到：看到 Backup for cloud 與 Backup for server／data center 等區塊。Data center 區塊裡有刪除所有 team-managed space 的按鈕，不要按。
  2. 你應該看到：下載一個 zip。
  3. 你應該看到：有 entities.xml 與 activeobjects.xml（資料庫內容），沒有附件、avatar 的資料夾。
  4. 你應該看到：多了 data/attachments、data/avatars、logos 等資料夾。
  5. 你應該看到：說明通常會提醒：匯入會取代站上現有的資料與設定。這就是「整站匯入＝覆蓋」，所以只在可丟棄的站台做。
  6. 你應該看到：有 add-on 的站台看得到 Restore a backup；選目的地時要用 Contain data = No 篩選，只能還原到沒有資料的 app。沒有 add-on 就只看得到介紹或購買頁。
  7. 你應該看到：CSV 匯入是把資料加入新的或現有 project，不是覆蓋整站。

試試看：改一個設定，觀察差異

通常會被擋下或提示要等：含附件、avatar 或 logo 的 backup 兩次之間要隔 48 小時。

心像錨點：閉上眼睛想一次這個畫面

Backup manager 頁上的 Create backup for cloud 與一個「包含附件」的勾選框；旁邊那顆匯入按鈕，你只看不按。備份不含自動化，整站匯入會覆蓋。

收尾

  • 下載的 backup 檔含整站資料（含使用者 email），用完妥善保管或移到垃圾桶；Backup manager 上的檔案過幾天會自動刪除。
  • 確認沒有啟動任何匯入或還原。
