120.1.1 使用者與產品存取5 條

把人加進 project role 就能使用 Jira。
還要 product access（Jira 授權）。
官方來源
Remove user 後 restore 就恢復原本的 group。
Remove 要重新邀請並重設；能完整還原的是 suspend。
官方來源
刪除 group 會一併刪掉成員。
成員還在；但用該 group 的權限會失效。
官方來源
公司 domain 的帳號都是 managed account。
要驗證 domain 並 claim 帳號才是 managed。
官方來源
Team-managed project 也能開放匿名瀏覽。
只有 company-managed 可以把 Browse 給 Public。
官方來源

120.1.2 Admin 權限4 條

Administer Jira 讓 Jira admin 管理使用者。
Administer Jira 本身不含管理使用者；一般使用者能否邀請人，取決於 organization 的 User invites 設定。
官方來源
Site admin 自動擁有 Administer Jira。
要加入 jira-administrators／jira-admins-xxx 才有；要用 Jira 的內容功能另需 Jira 的 user 角色。（集中式介面下，org admin 預設就有各 app 的 app admin 角色。）
官方來源
Project admin 能改 permission scheme。
Project admin 只管 role 成員；scheme 要 Jira admin。
官方來源
Site admin 可以指派另一個人為 site admin（集中式介面）。
只有 org admin 能指派 site admin。
官方來源

120.1.3 Global permissions4 條

Global permission 可以直接給單一使用者。
只能給 group。
官方來源
有 Make bulk changes 就能 bulk 編輯任何 project。
還要該 project 的對應權限（Edit、Transition、Delete、Move…）。
官方來源
沒有 Browse users and groups 就完全不能 @mention。
仍能 @mention 在該 project 有 Browse 權限的人。
官方來源
Create team-managed projects 可以建 company-managed project。
只能建 TMP；CMP 要 Administer Jira。
官方來源

120.1.4 Project permissions5 條

給了 Assign Issues，就能被指派。
被指派的人要 Assignable User。
官方來源
有 Move Issues 就能移到任何 project。
目標 project 也要 Create Issues。
官方來源
有 Link Issues 一定能連結。
Issue linking 全站關閉時，連 Link 選項都沒有。
官方來源
Project admin 可以改 permission scheme。
只能改 role 成員；scheme 要 Jira admin。
官方來源
Role 與 group 一樣都只能由 org admin 管。
Role 成員由 project admin 在 People 頁管。
官方來源

120.1.5 Issue-level security5 條

Sub-task 可以設成跟 parent 不同的 security level。
Sub-task 繼承 parent 的 level。
官方來源
有 Set Issue Security 就能選任何 level。
只能選自己是成員的 level。
官方來源
Issue security 可以讓沒有 Browse 的人看到 issue。
Issue security 只會在 Browse 之上再限制，不會額外開放。
官方來源
TMP 也能用 issue security scheme。
TMP 沒有 scheme；用限制 issue type 給特定 role。
官方來源
設好 scheme 就一定看得到 Security Level 欄位。
欄位要放上 screen（或 layout）。
官方來源

120.2.1 Project 類型與 template4 條

TMP 可以和另一個 TMP 共用 workflow。
TMP 的設定只屬於自己。
官方來源
選了 Kanban template 就是 team-managed。
Template 決定工作方式；管理方式要另外選。
官方來源
共用設定後，在 project B 改 workflow 只影響 B。
Scheme 共用，A 也會一起變。
官方來源
一般使用者可以建 company-managed project。
要 Administer Jira。
官方來源

120.2.2 Project details4 條

Project admin 能改 project key。
要 Jira admin（或 org、site admin）。
官方來源
改 key 會讓舊連結全部失效。
舊 key 會被保留，舊連結繼續有效。
官方來源
Default assignee 可以設任何成員。
只能 Unassigned 或 project lead。
官方來源
改 key 後舊 key 可以給新 project 用。
Previous key 不能再被使用。
官方來源

120.2.3 Versions4 條

有未解決的 issue 就不能 release。
可以：移到其他 version 或忽略後照樣發布。
官方來源
Merge 之後來源 version 仍保留。
來源 version 會被刪除。
官方來源
同一個 project 可以有兩個 v1.0。
Version 名稱在 project 內唯一。
官方來源
Kanban 一定要事先把 issue 指到 version。
Kanban 可以隨時 release 已完成的工作，release 時才命名。
官方來源

120.2.4 Components 與自動指派4 條

多個 component 衝突時一律 Unassigned。
有 Component lead 就是他；依類型優先序。
官方來源
多個 component 依 lead 的名字排序。
先比類型；都是 Component lead 時才依 component 名稱字母序，不是 lead 的名字。
官方來源
TMP 也能用 component 自動指派。
Components 只在 CMP。
官方來源
Component lead 沒有 Assignable User 也會被指派。
會被跳過。
官方來源

120.3.1 Issue types4 條

改 issue type 名稱只影響目前 project。
Issue type 是全站物件，所有 project 都會變。
官方來源
建了 issue type 就會自動出現在所有 project。
要加進 project 使用的 issue type scheme。
官方來源
Sub-task 可以放在和 parent 不同的 project。
Sub-task 與 parent 同 project。
官方來源
TMP 的 issue type 要 Jira admin 建。
TMP 的 project admin 自己建。
官方來源

120.3.2 Fields5 條

一個 project 可以同時屬於同一欄位的兩個 context。
一個 project 只能屬於一個 context。
官方來源
要不同選項就建另一個同名欄位。
建另一個 context 即可。
官方來源
欄位在 screen 上就一定看得到。
Field configuration 設 Hide 時仍看不到；context 不含也看不到。
官方來源
Required 只在 Create 畫面檢查。
建立與編輯都檢查。
官方來源
刪除 custom field 立刻永久消失。
標記 60 天後刪除，期間可 restore。
官方來源

120.3.3 Screens 與 issue layout4 條

Project admin 可以把新欄位加到 screen。
改 screen 要 Jira admin；project admin 只能在 layout 排列現有欄位。
官方來源
Copy issue layout 會讓兩個 project 之後一起變。
不建立連結；之後各自獨立。
官方來源
Issue type screen scheme 直接對應 screen。
它對應的是 screen scheme，screen scheme 再對應 screen。
官方來源
Hide when empty 以下的欄位永遠看不到。
有值時會移到 Details 顯示。
官方來源

120.4.1 CMP workflows4 條

Status 是 Done 就一定會被 resolution = Unresolved 排除。
看的是 resolution 欄位，不是 status。
官方來源
Validator 會讓沒權限的人看不到按鈕。
藏按鈕的是 condition；validator 在提交時才檢查。
官方來源
在 workflow 加了 status，board 會自動多一欄。
要在 board 設定把 status map 到欄位。
官方來源
Custom event 建好就會寄信。
要在 transition 的 post function 觸發，並在 notification scheme 設收件人。
官方來源

120.4.2 TMP workflows4 條

TMP 所有 issue type 共用一個 workflow。
每個 issue type 可以有自己的 workflow。
官方來源
TMP 的 workflow 要 Jira admin 改。
Project admin 就能改。
官方來源
TMP 改 status 名稱會影響其他 project。
只影響這個 project。
官方來源
TMP 不能限制誰能移動 issue。
可以用 Restrict who can move a work item rule。
官方來源

120.4.3 Automation rules4 條

Project admin 可以建跨多個 project 的 rule。
要 Jira admin（global automation）。
官方來源
Rule 一定成功，因為 automation 不受權限限制。
Rule 以 actor 執行，actor 缺權限就會失敗。
官方來源
要改 sub-task 直接在 action 選就好，不用 branch。
要用 branch 對每個 sub-task 執行。
官方來源
一條 rule 可以有多個 trigger。
只能一個（可用 Multiple work item events）。
官方來源

120.5.1 CMP notification scheme4 條

Notification scheme 設了 group，group 成員就一定收得到。
還要能 Browse 該 issue（含 issue security）；個人設定也可能關掉。
官方來源
Custom event 建好就會自動觸發。
要在 transition 的 post function 觸發。
官方來源
Project admin 可以改 notification scheme。
要 Jira admin。
官方來源
所有 transition 都觸發 Issue Updated。
依 post function 設定的 event（常見 Generic Event、Issue Resolved…）。
官方來源

120.5.2 TMP 通知3 條

TMP 的通知要 Jira admin 改 notification scheme。
TMP 沒有 scheme；project admin 自己設。
官方來源
刪除 role 後相關通知會自動移除。
通知會失效，但要手動移除。
官方來源
TMP 不能改寄件 email。
可以設定 project 的 notification email。
官方來源

120.5.3 個人通知設定3 條

個人設定可以讓使用者收到 admin 沒設定的通知。
個人設定只是濾網。
官方來源
關掉 issue 活動 email 就什麼信都不會收。
Filter subscription、站台公告等仍會寄。
官方來源
每個變更都會立即寄一封。
零碎更新可能延遲最多 10 分鐘合併成摘要；重要通知立即寄。
官方來源

120.5.4 Mail handlers4 條

CC assignee 會指派給 To 欄位的第一個人。
先看 CC，再 To，再 BCC。
官方來源
沒有 Jira 帳號的人寄信一定建不了 issue。
設 default reporter 即可。
官方來源
一個 handler 可以設多個 catch email address。
只能一個。
官方來源
Project admin 可以設定 mail handler。
要 Administer Jira（Jira admin）。
官方來源

120.6.1 進階 JQL4 條

status = Done 等於已解決。
已解決看 resolution；未解決用 resolution = Unresolved。
官方來源
CHANGED 會找出建立時就是該值的 issue。
CHANGED 只找有改過的；WAS 才包含建立時的值。
官方來源
混用 AND 與 OR 時不必加括號，Jira 會照你的意思分組。
官方：沒有括號時由左到右計算；要表達「A 且（B 或 C）」一定要加括號。
官方來源
Basic search 可以做任何 JQL 能做的事。
不能跨欄位 OR、不能括號、不能歷史查詢。
官方來源

120.6.2 Filters、dashboards、subscriptions4 條

訂閱給 group 時，所有人收到的是建立者看到的結果。
每人依自己的權限與 currentUser() 計算。
官方來源
沒結果也會寄空白信。
預設不寄，要勾選才寄。
官方來源
任何人都能把 filter 分享給 group。
要 Share dashboards and filters 全域權限。
官方來源
任何人都能訂閱給 group。
要 Manage group filter subscriptions。
官方來源

120.6.3 Bulk operations5 條

有 Make bulk changes 就能 bulk 做任何事。
還要對應的 project 權限。
官方來源
可以一次 bulk 改 5,000 個 issue。
一次最多 1,000 個。
官方來源
不同 workflow 的 issue 可以一起 bulk transition。
要依 workflow 分組，一次一組。
官方來源
Bulk 一定會寄通知。
多數操作可取消勾選 Send mail for this update。
官方來源
CMP 移到 TMP 後 components 還在，只是隱藏。
永久移除。
官方來源

120.7.1 全站介面設定4 條

改 user default settings 會立刻改變所有既有使用者。
只在建立帳號時套用；只有 Email format 能用 Apply 強制全體。
官方來源
Announcement banner 只能給登入者看。
可以設成 public。
官方來源
Project admin 能改 default dashboard。
要 Jira admin。
官方來源
個人設定會被 default 覆蓋。
個人設定優先。
官方來源

120.7.2 附件、連結、time tracking4 條

有 Link Issues 權限就一定能連結。
全站 issue linking 關閉時不行。
官方來源
關閉 time tracking 會刪除所有工時紀錄。
只是隱藏，重新開啟就恢復。
官方來源
Board 的 estimation statistic 就是全站 time tracking 設定。
兩者不同。
官方來源
Link type 只有一個描述。
有 outward 與 inward 兩個描述。
官方來源

120.7.3 Status、resolution、priority4 條

在 CMP 改 status 名稱只影響目前 project。
Status 是全站物件。
官方來源
TMP 改 status 名稱會影響全站。
只影響該 TMP。
官方來源
有 sub-task 也能直接停用 sub-tasks。
要先轉換既有 sub-task。
官方來源
所有 project 只能用同一套 priority。
可以用 priority scheme。
官方來源

120.7.4 Backup 與 import6 條

Backup 包含 automation rules。
不包含；要另外匯出、匯入。
官方來源
可以每小時做一次含附件的 backup。
含附件時間隔至少 48 小時。
官方來源
匯入 backup 會和現有資料合併。
會覆蓋現有資料。
官方來源
有 Administer Jira 就能匯入 backup。
Jira admin 只能建立 backup；匯入 backup 要 org admin（官方 Learning 課程；global permissions 頁另寫 Administer Jira 不含匯入匯出，兩處說法不一）。
官方來源
調整 backup 檔就能只匯入某個 project。
不行；只能選要不要匯入資料庫、附件、avatar、logo。
官方來源
Atlassian Backup & Restore 可以還原到正在使用的站台。
只能還原到沒有資料的 app。
官方來源
