3 分鐘速覽

TMP workflow：每個 issue type 一個，project admin 自己改

  1. 每個 issue type 各自的 workflowProject settings → Issue types → 選 type → Edit workflow。
  2. Status 與 board 欄位連動在 board 加一欄＝加一個 status；status 的 category 決定 To do、In progress、Done。
  3. Transitions可以從任何 status（Any status）或指定 status 轉入。
  4. Rules：restrict限制誰能移動（assignee、reporter、user、role、group、permission）、要經過某 status、欄位值條件、驗證權限。
  5. Rules：update自動指派（reporter、current user、no one、某人）、更新欄位、複製欄位值。
  6. 必填欄位最可靠：在 work type 的欄位勾 Required（建立時就必填）。官方兩頁 rule 清單不一致：Available workflow rules 頁沒有必填類 rule，Add or remove workflow rules 頁另列 Remind people to update empty fields。

Workflow rules

TMP 的兩類 rule：restrict 與 update

類別Rule例子
Restrict（類似 condition）Restrict who can move a work item只有 QA role 能從 In review 移出
Restrict to when a work item has been through a status轉 Done 前最近的 status 必須是 In review
Restrict to when a work item is a specific valuePriority = Highest 才能走 Expedite
Validate that people have a specific permission有 Assign 權限才能開始
Update（類似 post function）Assign a work item to someone到 In review 時指派給 QA
Update a work item field／Copy the value of one field to another到 Done 時設欄位、複製值
官方兩頁的清單不一樣

上表依 Available workflow rules 頁。Add or remove workflow rules 頁列的是 5 條：Assign a work item to someone、Update a work item field、Restrict who can move a work item、Remind people to update empty fields、Check that a work item has been through a status。名稱與數量隨版本變動，考試以 restrict（類似 condition／validator）與 update（類似 post function）兩類的概念作答。

本段必考
  • TMP 的 rule 對應 CMP 的 condition／validator／post function。

Status 與欄位

建立、編輯、刪除

  1. 建 statusWorkflow editor 加 status，或在 board 加欄位（同時建 status）。
  2. Category每個 status 選 To do、In progress、Done；決定 board 與報表的分類。
  3. 改名TMP 改 status 名稱只影響這個 project（status 屬於該 project）。
  4. 刪除有 issue 在該 status 時，要先選把它們移到哪個 status。
  5. Transition建立轉換，可勾 Allow all statuses to transition to this one。

動手做

實作 Lab：在 TEAM 的 workflow 加 status 與 rules

約 25 分鐘TEAM 的 Administrator（project admin 就夠，不用 Jira admin）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：用 project admin 的身分改 TEAM 的 Task workflow：加 status、看 board 欄位連動、加 restrict 與 update 兩類 rule，再用 Leo 驗證。

這個 Lab 對應的考點

TMP 每個 issue type 可以有自己的 workflow，project admin 自己改；status 與 board 欄位連動；rules 分成 restrict（像 condition）與 update（像 post function）；必填是在 work type 的欄位上勾 Required。TMP 改 status 名稱只影響這個 project。

準備

  • Leo 在 TEAM 是 Member（Space settings → Access → Add people → Role 選 Member）。
  • TEAM 有幾張 To do 的 Task。

步驟

  1. 你應該看到：Task 的 workflow 圖：status 依 category（To do、In progress、Done）分色，有 Any status 的轉入。
  2. 你應該看到：Task 有了 In Review，Bug 不受影響。新 status 預設不在任何 board 欄位，board 上看不到；可以在 workflow editor 或 Space settings → Board → Columns and statuses 把它放進欄位。
  3. 你應該看到：Workflow 多了 QA status：在 board 加一欄＝加一個 status。
  4. 你應該看到：Rules 分兩類：限制誰／什麼時候能移動（restrict），與移動時自動指派、改欄位（update）。對照教材的清單；Atlassian 改版時清單可能略有出入。
  5. 你應該看到：Leo 移不過去；你可以。
  6. 你應該看到：被擋；先到 In Review、再到 Done 就可以。
  7. 你應該看到：Assignee 自動變成 Leo：update 類 rule，像 CMP 的 post function。
  8. 你應該看到：建立不了：TMP 的必填是在欄位上設定，不是 workflow rule。

試試看：改一個設定，觀察差異

T1在 Task 的 workflow 把 In Review 改名 Peer Review → Update workflow；再看 WEB 的 status。看結果
只有 TEAM 變，WEB 不受影響。如果這個 status 被 TEAM 裡其他 work type 共用，它們也會一起改名（可以選只改這個 workflow）。
T2把一張 Task 留在 Peer Review，然後在 workflow 刪除 Peer Review → Update workflow。看結果
Jira 警告有 issue 在要刪的 status，要你把它們移到有效的 status。刪 status 也會刪掉相關的 transition 與 rule。
T3加 Restrict to when a work item is a specific value：進入 In Review 時 Priority 必須 equals Highest。分別拖一張 Highest 與一張 Medium 的 Task。看結果
只有 Highest 那張過得去：rule 先看欄位值，再決定這條路能不能走。
心像錨點：閉上眼睛想一次這個畫面

TMP workflow editor 上方工具列：三個 category 色塊、Transition、Rules。Rules 只有兩種脾氣：限制誰能走、走了自動改。

收尾

  • 刪除這次加的 rule；取消 Due date 的 Required。
  • 把 issue 移出 In Review（Peer Review）與 QA，再刪掉這兩個 status 與 QA 欄。
  • Leo 可以留在 TEAM 當 Member，或從 Access 移除。
