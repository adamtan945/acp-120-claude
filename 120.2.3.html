Versions

Version 把工作分批發布。考你 release 未完成工作的處理、merge 與 delete 的影響，以及命名規則。

3 分鐘速覽

Version：一起發布的一組工作

  1. Fix version這張 issue 會在哪個版本完成；Affects version：問題出現在哪個版本。
  2. 名稱在 project 內唯一同一個 project 不能有兩個同名 version。
  3. Release 時有未解決的 issue選擇移到另一個 version，或忽略並照樣發布。
  4. Merge把多個 version 的 issue 併到一個 version；被併的 version 會刪除。
  5. Delete要決定 Fix／Affects version 的 issue 改指到哪個 version，或直接移除。
  6. Scrum vs KanbanScrum 先規劃再發布；Kanban 隨時發布已完成的工作，發布時才命名。
操作

Release、merge、delete、archive

動作做什麼對 issue 的影響
Release標記版本已發布、設 release date有未解決 issue → 移到其他 version 或忽略
Unrelease取消發布—
Merge把 A、B 合到 CA、B 的 issue 改指到 C；A、B 被刪除
Delete刪除 versionFix／Affects version 改指到別的 version 或移除
Archive從大部分清單隱藏，但保留Issue 仍保留該 version
本段必考
  • Release 有未完成 → 移走或忽略。
  • Merge 後來源 version 消失。
權限

誰能管 version

  • Project admin（Administer Projects）或有 Manage versions 權限的人可以建立、發布、合併、刪除 version。
  • 設定 issue 的 Fix version 要 Edit Issues（或 Resolve Issues 視 screen 而定）。
  • TMP 要先開 Releases 功能，只有 Fix versions，沒有 Affects versions。
本段必考
  • 名稱在 project 內唯一。
