3 分鐘速覽

Permission scheme（CMP）vs access＋role（TMP）

  1. CMP：permission schemeJira admin 建 scheme、把權限給 role、group、user、reporter、assignee、project lead、user／group custom field、Application access、Public。
  2. TMP：access level＋roleOpen／Limited／Private＋Viewer／Member／Administrator（與自訂 role）；project admin 自己管。
  3. Role vs groupRole 讓同一個 scheme 用在多個 project、由 project admin 管成員；group 是全站、由 org admin 管。
  4. 權限要成對Assign Issues＋Assignable User；Resolve Issues＋Transition；Move Issues＋目標 project 的 Create；Link Issues＋全站開 issue linking。
  5. User custom field把權限給「欄位裡的人」，例如 Approver 欄位的人可以 Transition。
  6. Project adminAdminister Projects：管 role 成員、components、versions、details；不能改 scheme。

動手做

實作 Lab：Assign、Assignable 與 Public

約 25 分鐘Jira admin；Standard 以上

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在 WEB Permission Scheme 拆開兩個成對的權限，看指派下拉選單的變化；再把 WEB 開放給未登入的路人看。

這個 Lab 對應的考點

Assign Issues＋Assignable User 要成對；權限給 role 讓 project admin 自己管人；Public 只能給 Browse、Create 這類不需授權的權限。

準備

  • WEB 使用 WEB Permission Scheme（見 Lab 環境準備）。
  • Leo 在 Developers，Kim 在 Users（或 Viewers）。

步驟

  1. 你應該看到：兩個都給了某些 role（例如 Developers、Administrators）。
  2. 你應該看到：下拉清單有 Leo，沒有 Kim（Kim 不在有 Assignable User 的 role）。
  3. 你應該看到：Assignable User 多了 Users。
  4. 你應該看到：Kim 出現在清單了；但 Kim 自己仍不能指派別人（沒有 Assign Issues）。
  5. 你應該看到：Kim 又從清單消失。
  6. 你應該看到：未登入也看得到 WEB 的 issue；但沒有 Edit、Assign 按鈕（Public 只能給不需 Jira 授權的權限）。
  7. 你應該看到：又要求登入。

試試看：改一個設定，觀察差異

T1把 Transition Issues 從 Developers 移除，用 Leo 打開 issue。看結果
Leo 看得到 issue，但狀態按鈕無法轉換。轉到 Done 要 Transition；要設 Resolution 還要 Resolve Issues。做完記得加回。
T2試著在 Edit Issues 那一列選 Public。看結果
選不到或無法儲存：Edit 只能給受邀（有授權）的使用者。
T3到 TEAM 的 Space settings → Access，把 access 從 Open 改成 Limited，用 Kim 打開 TEAM。看結果
Kim 變成 Viewer：看得到、能留言，但不能建立或編輯 work item。做完改回 Open。
心像錨點：閉上眼睛想一次這個畫面

Permission scheme 頁：一列一個權限，右邊是給了誰（role、group、Public…），每列有 Update。Assign 與 Assignable 是相鄰的兩列，要一起看。

收尾

  • 確認 Browse Projects 沒有 Public、Assignable User 與 Transition Issues 已回到原狀。
  • TEAM 的 access 改回 Open。
