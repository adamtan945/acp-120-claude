3 分鐘速覽

三種 admin：org admin、Jira admin、project admin

  1. Org admin最高：管使用者、group、app 存取、安全政策；唯一能指派其他 org admin、site admin、Jira 的 app admin。
  2. Site admin管理 site 上的 app 與 Marketplace app；要有 Jira 授權才能用 Jira 功能。
  3. Jira admin（app admin）Administer Jira 全域權限；建 project、改 scheme、workflow、欄位。不能管使用者、不能匯入匯出、不能改系統 email。
  4. Project adminAdminister Projects 權限（CMP）或 Administrator role（TMP）；只管自己的 project。
  5. Org／site admin 與 Administer Jira原始介面要把自己加進 jira-administrators；集中式介面下 org admin 預設有各 app 的 app admin 角色（可被移除）。
  6. 用 group 授權 admin把人加進 admin 的 default group，例如 jira-admins-xxx、org-admins。

授權方式

怎麼把人變成 admin

  1. Org adminAtlassian Administration → Directory → Users → 選人 → ••• → Assign organization admin role（只有 org admin 能做）。
  2. Site admin選人 → ••• → Assign site admin role（只有 org admin）。
  3. Jira admin（app admin）選人 → Grant access → Jira Administration 選 App admin（只有 org admin 能指派 Jira 的 app admin）。或加進 jira-admins-xxx group。
  4. Project adminJira admin 在 permission scheme 把 Administer Projects 給 Administrators role；project admin 再把人加進該 role。TMP 則直接給 Administrator role。
admin 不等於有授權

易錯觀念

考題愛用的錯誤說法

Administer Jira 讓 Jira admin 管理使用者。
Administer Jira 本身不含管理使用者；一般使用者能否邀請人，取決於 organization 的 User invites 設定。
官方來源
Site admin 自動擁有 Administer Jira。
要加入 jira-administrators／jira-admins-xxx 才有；要用 Jira 的內容功能另需 Jira 的 user 角色。（集中式介面下，org admin 預設就有各 app 的 app admin 角色。）
官方來源
Project admin 能改 permission scheme。
Project admin 只管 role 成員；scheme 要 Jira admin。
官方來源
Site admin 可以指派另一個人為 site admin（集中式介面）。
只有 org admin 能指派 site admin。
官方來源

動手做

實作 Lab：把 Leo 變成 Jira admin，再收回

約 15 分鐘Org admin（只有 org admin 能指派 Jira 的 app admin）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：看 Leo 在三種身分下（一般使用者 → Jira admin → project admin）的 ⚙ Settings 選單差在哪裡。

這個 Lab 對應的考點

Org admin 是唯一能指派 org、site、Jira app admin 的人；Jira admin 管設定、不管使用者；project admin 只管自己的 project。

準備

  • Leo 是一般使用者（不在任何 admin group）。

步驟

  1. 你應該看到：Leo 看不到 Jira 的系統設定（沒有 Work items、System 這類全站設定）。
  2. 你應該看到：Leo 的角色清單多了 Jira 的 App admin；group 清單多了 jira-admins-xxx。
  3. 你應該看到：Leo 看得到 Work items、System 等全站設定，可以打開 Permission schemes。
  4. 你應該看到：Leo 不能管理 organization 的使用者（app admin 不能進 Atlassian Administration 管人）。
  5. 你應該看到：Leo 重新整理後，⚙ 選單又只剩個人設定。
  6. 你應該看到：Leo 看得到 WEB 的 Space settings（details、components、versions、people），但 ⚙ 裡仍沒有全站設定。這就是 project admin。

試試看：改一個設定，觀察差異

T1用 Leo（project admin）在 WEB 的 Space settings → Permissions 試著改 permission scheme。看結果
只能看、不能改 scheme 的內容；換 scheme 也要 Jira admin。Project admin 管 role 成員，不管 scheme。
T2用 Leo（project admin）在 WEB 的 Details 改 project key。看結果
改不了：只有 org、site、Jira admin 能改 project key。
心像錨點：閉上眼睛想一次這個畫面

admin.atlassian.com 的 Leo 頁面 → Grant access 對話框：每個 app 一列、Roles 一欄，選 App admin。這個按鈕只有 org admin 按得到。

收尾

  • 把 Leo 從 WEB 的 Administrators role 移除，留在 Developers。
  • 確認 Leo 沒有 Jira App admin 角色。
