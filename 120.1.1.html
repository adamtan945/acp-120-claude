3 分鐘速覽

帳號、產品存取、群組與匿名存取

  1. Atlassian account → organization → site → app一個帳號可以在多個 organization；app 存取（product access）才決定能不能用 Jira。
  2. Product access給使用者 app 角色（User、Admin…）＝加進該角色的 default group；佔授權的是有 User 角色的人。
  3. Managed vs external驗證 domain 並 claim 的帳號＝managed，可改資料、停用、刪除；其他都是 external user。
  4. Remove vs suspendRemove：移出 organization、要重新邀請並重設 group；Suspend：暫停、不計費，Restore 後角色與 group 回來。
  5. 刪除 group不會刪除使用者；用這個 group 設定的權限會失效；default group 不能刪。
  6. 匿名存取Permission scheme 把 Browse Projects 給 Public（Anyone on the web）；只有 company-managed 可以。

考題長相

「使用者被加進 project role，卻無法登入 Jira」→ 他沒有 Jira 的 product access。Role 與 permission 都無法取代授權。（例外：Browse、Create 這類權限可給 Public，讓未授權者匿名瀏覽或提單，但仍不能編輯、指派。）

本段必考
  • 沒有 product access 就不是 Jira 使用者，不能編輯、指派；Browse／Create 可給 Public 是例外。

Product access

給、收回 app 存取

  • 給使用者 app 存取＝把他加進該 app 角色的 default group（例如 jira-users-xxx）；也可以直接把人加進這個 group。
  • Approved domains：設定後，使用公司 domain 的人不用邀請就能加入並取得指定的 app 存取；勾 Required 時要 admin 核准，取消才是即時加入。User invites 設成 Invite anyone 時，現有使用者也能邀請任何人。
  • Invite user：邀請時選要給哪些 app、加進哪些 group。
  • Product access requests：使用者可以申請存取，admin 核准或拒絕。
  • 收回存取：移除 app 角色或從 default group 移除；使用者仍在 organization，但不能用該 app。
本段必考
  • Default group＝授權入口。
  • Approved domains＝同公司 domain 自助加入。

Groups 與匿名

群組、刪群組、公開 project

  • Group 是全站的使用者集合，由 org admin（或 user access admin）管理；global permission 只能給 group。
  • 刪除 group：使用者不會被刪；透過該 group 給的權限不再對原成員生效（常見位置：permission scheme、global permissions、notification scheme、filter 分享、issue security）。官方建議先移除權限再刪除，否則日後重建同名 group 時權限會自動回來；app 角色的 default group 不能刪。
  • 匿名（anonymous）存取：permission scheme 把 Browse Projects 給 Public（Anyone on the web）。考綱稱 unlicensed／anonymous access；team-managed project 不支援匿名。
  • 防止或移除公開存取：檢查 permission scheme 是否把 Browse 給 Public、filter 與 dashboard 是否分享給 Public；General configuration 的 Public sharing 可關掉 filter／dashboard 公開分享（不會收回已分享的）。Free 方案的 project 不能公開。
公開前三思

Browse Projects 給 Public 之後，任何能連到站台的人（含未登入）都能看 issue。Filter、dashboard 分享給 Public 也一樣。

本段必考
  • 刪 group＝相關權限一起消失。
  • 匿名＝Browse Projects 給 Public，只有 CMP。
資料來源（5）有疑慮時點開看官方原文
  • Delete a groupThis prevents any permissions from being automatically assigned in an app if a group is created with this name again.
  • Delete a groupYou can’t delete a group if it’s a default group for a role.
  • Allow dashboards and filters in your site to be shared publiclyTurning Public sharing off prevents new and not-yet-shared dashboards and filters from being shared.
  • Team-managed space permissionsCurrently, you can't allow anonymous access to a team-managed space.
  • Use permissions to make a space publicly visibleSpaces from Free Jira sites can’t be opened to the public.

動手做

實作 Lab：收回、暫停、還原一個人的存取

約 20 分鐘Org admin；Standard 以上（試試看 T2 要改 permission scheme）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：親手做一次 product access 的給與收，以及 suspend 與 remove 的差別；再看刪除 group 對權限的影響。

這個 Lab 對應的考點

Product access＝能不能用 Jira；suspend 可完整還原、remove 要重設；刪 group 後重建同名 group，權限會自動回來。

準備

  • Kim 已接受邀請、能進 Jira。
  • Kim 已在 hr-team 以外的任一個 group（例如自建 lab-temp）。

步驟

  1. 你應該看到：Jira 的角色是 User，group 清單裡有 jira-users-xxx 與 lab-temp。
  2. 你應該看到：Kim 無法使用 Jira；但 Kim 仍在 Users 清單，仍是 organization 的成員。
  3. 你應該看到：Kim 重新整理後又能進 Jira。
  4. 你應該看到：Kim 的狀態變成已暫停；Kim 的瀏覽器重新整理後無法使用。
  5. 你應該看到：角色與 group（含 lab-temp）都回來了，跟步驟 1 記下的一樣。
  6. 你應該看到：知道「同公司 domain 自助加入」與「誰可以邀請人」這兩個設定在同一區。

試試看：改一個設定，觀察差異

T1（想像，不實際做）如果步驟 4 改成 Remove user，再重新邀請 Kim，lab-temp 會回來嗎？看結果
不會。Remove 後重新邀請，要重新指定角色與 group；只有 suspend → restore 會完整回來。
T2建一個 group lab-ghost，到 ⚙ Settings›Work items›Permission schemes›WEB Permission Scheme 把 Browse Projects 給 lab-ghost。然後刪除 lab-ghost（Directory›Groups → lab-ghost → ••• → Delete group），回 permission scheme 看；再建一個同名的 lab-ghost，再看一次。看結果
刪除後 Browse Projects 那一列的 lab-ghost 不見了（或失效）；重建同名 group 後，權限又出現。這就是官方建議「刪 group 前先移除它的權限」的原因。
T3用無痕視窗（未登入）打開 WEB 的網址。看結果
要求登入：WEB 沒有把 Browse Projects 給 Public。120.1.4 的 Lab 會把它打開。
心像錨點：閉上眼睛想一次這個畫面

Users 頁 Kim 那一列的 ••• 選單：Suspend access 與 Remove user 上下並排。Suspend 會回來，Remove 要重來。

收尾

  • 刪除 lab-ghost 與它在 WEB Permission Scheme 的權限（順序：先權限、再 group）。
  • 確認 Kim 的 Jira 角色是 User、狀態不是暫停。
