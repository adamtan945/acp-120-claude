3 分鐘速覽

Mail handler：email 變成 issue 或留言

  1. 設定位置Settings → System → Mail → Incoming Mail：先有 mail server（Google、Microsoft 用 OAuth；或 POP／IMAP），再加 mail handler。
  2. Handler 類型Create or comment（主旨有 issue key 就留言，沒有就建 issue）、只建 issue、只留言（全文、去除引用、marker 之前）。
  3. Default reporter寄件人不是 Jira 使用者時用這個帳號當 reporter（要有 Create Issues）；原寄件人寫在 description 末尾。
  4. CC assignee指派給第一個 CC 的使用者；沒有就看 To、再看 BCC；都沒有就不由 handler 指派。
  5. 其他選項Project、issue type、strip quotes、catch email address、bulk（ignore／forward／delete／accept）、forward email、CC watchers。
  6. 限制超過 7 天的信不處理；SPF 驗證失敗會被拒。

動手做

實作 Lab：寄一封信，變成 WEB 的 work item

約 30 分鐘Jira admin（Administer Jira）；實際寄信測試要一個專用的測試信箱

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：設一個 Create or comment 類型的 mail handler，實際寄信看：主旨沒 key 會建單、有 key 會留言、陌生寄件人靠 default reporter、CC 的人變成 assignee。

這個 Lab 對應的考點

主旨有 issue key → 留言，沒有 → 建 issue；寄件人不是 Jira 使用者要靠 Default reporter；CC assignee 依 CC → To → BCC 找第一個有效使用者，都沒有就不由 handler 指派。

準備

  • 前提：另開一個只給 Jira 收信用的 Gmail（以下叫 lab 信箱），不要用你的私人或公司信箱。Gmail 要用 Sign in with Google（OAuth）連線。沒有這個信箱，就只做步驟 1、3（看設定畫面），步驟 4～7 用下面的「你應該看到」推演。
  • Leo 在 WEB 的 Developers（有 Create Issues，也是可指派的人）。
  • 記下 Leo 的 email（你的別名，例如 你的帳號+leo@gmail.com）。

步驟

  1. 你應該看到：看到站台預設的 mail server 與 Default email handler，handler params 類似 createusers=false,…,stripquotes=true,bulk=ignore。
  2. 你應該看到：清單多一個 lab 信箱的 mail server。登入失敗的 server 雖然在清單上，但設定 handler 時選不到。
  3. 你應該看到：Incoming Mail 頁的 handler 清單多了 Lab WEB handler。沒有 lab 信箱就停在 Next 後的選項頁，看完這些欄位按取消。
  4. 你應該看到：WEB 多一張 Task：summary 是 Lab mail 1，reporter 是你，assignee 是 Leo（CC 裡第一個有效使用者）。lab 信箱裡那封信被標成已讀。
  5. 你應該看到：沒有建新單；WEB-xx 多了一則留言，留言者是你。主旨有 key ＝ 留言。
  6. 你應該看到：WEB 多一張 Task：reporter 是 Leo（default reporter），description 最後一段寫著原寄件人的 email；assignee 不是 handler 指派的，通常依 WEB 的預設指派規則（例如 Unassigned 或 project lead）。
  7. 你應該看到：Assignee 是 Leo：CC 裡找不到有效使用者時，handler 改看 To。

試試看：改一個設定，觀察差異

T1編輯 Lab WEB handler，清空 Default Reporter，再用 lab 信箱寄一封。看結果
通常不會建出 work item：寄件人不是 Jira 使用者、又沒有 default reporter。若有設 Forward Email，可能會收到處理失敗的通知。做完把 Default Reporter 填回。
T2用你的主信箱寄一封沒有主旨的信。看結果
不會被處理：主旨是 summary 的來源，沒有主旨的信不處理。
T3（想像，不實際做）同一個 handler 想要只收寄給兩個不同別名的信。看結果
做不到：一個 handler 只能設一個 Catch Email Address（和一個 work type）。要兩個就建兩個 handler。
心像錨點：閉上眼睛想一次這個畫面

Incoming Mail 頁：上面是 mail server、下面是 mail handler。信的主旨有 key 就變留言，沒有 key 就開新單；陌生人靠 Default Reporter 才進得來。

收尾

  • 先刪 Lab WEB handler，再刪 lab 信箱的 mail server（先刪 server 會讓 handler 行為異常）。
  • 測試建立的 WEB Task 可以留著，或之後在 120.6.3 用 bulk 一起處理。
