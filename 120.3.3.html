Screens 與 issue layout

3 分鐘速覽

Screen 三層＋issue layout

  1. Screen一組欄位（可有 tabs）；Jira admin 建立。
  2. Screen scheme依操作對應 screen：Create、Edit、View。
  3. Issue type screen scheme依 issue type 對應 screen scheme；套到 project。
  4. Transition screenWorkflow transition 上也可以掛 screen（例如 Resolve 時填 resolution）。
  5. Issue layoutProject admin 決定欄位在 issue view 的 description、context（含 hide when empty）、hidden 區。
  6. Copy issue layoutJira admin 可把 layout 複製到使用同一個 screen 的其他 project（覆蓋、不連動）。

Issue layout

Issue view 的欄位排列

  • Project settings → Issue layout（或 issue 上 Configure → Issue view）。
  • Description fields：左側（主要內容）；有 tabs 時也在這區。
  • Context fields：右側 Details；有 Hide when empty 分隔線：線以下的欄位沒值時收在 More fields。
  • Hidden fields：完全不顯示在 issue view。
  • 共用同一個 view screen 的 issue type 會一起設定。
  • 能加到 layout 的欄位＝view screen 上有的欄位；要加新欄位或 tab 要 Jira admin 改 screen。
  • Copy issue layout（Jira admin）：複製到使用相同 screen 的其他 project；會覆蓋對方、之後不連動。
本段必考
  • Layout 只排列、不新增欄位。
  • Copy layout 會覆蓋、不連動。
TMP

Team-managed 的畫面

  • TMP 沒有 screen 與 scheme：每個 issue type 的欄位直接在 Project settings → Issue types 拖拉。
  • 欄位分成 Description fields、Context fields（含 hide when empty）與「建立時顯示」的設定。
  • 考試版：TMP 不能替 transition 加 screen。
本段必考
  • TMP 用 issue type 設定欄位，沒有 screen scheme。
