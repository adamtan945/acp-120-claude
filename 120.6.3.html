3 分鐘速覽

Bulk change：一次改很多

  1. 權限Make bulk changes 全域權限＋每個動作對應的 project 權限（Edit、Transition、Move、Delete…）。
  2. 上限一次最多 1,000 個 issue。
  3. 五種操作Edit、Transition、Move、Delete、Watch／Unwatch。
  4. Transition一次只能一個 transition；不同 workflow 的 issue 要分組；要填 transition 要求的欄位。
  5. 通知可取消勾選 Send mail for this update（不是每種操作都有）。
  6. Move要對應 status 與欄位；CMP → TMP 會永久失去 components 與 versions。

  • 多值欄位注意 replace 與 add。
Bulk move

跨 project 移動與 CMP↔TMP

  1. 選目標Destination project 與 issue type。
  2. 對應 status目標 workflow 的 status 不同時，選每個舊 status 要變成哪個新 status（建議對應同 category）。
  3. 更新欄位目標要求的必填欄位要給值；同類型、同名的 custom field 可以 Retain。
  4. 確認Review → Confirm。
CMP → TMP 會失去說明
Components永久遺失；移回 CMP 也救不回
Versions／releases永久遺失；即使 TMP 開了 Releases 也一樣
Sprints不會搬過去；issue 進到 TMP 的 backlog
Story points遺失；在 TMP 開 Estimation 後重新估
報表歷史Velocity、burnup 等歷史全部遺失
Global custom field 的值資料保留但在 TMP 顯示為空白（TMP 欄位是另一套）；欄位要在 TMP 重建
Issue key自動改成新 key，舊連結會轉址
