3 分鐘速覽

先選管理方式，再選工作方式

  1. Company-managed（CMP）設定是 scheme、可跨 project 共用；Jira admin 管；有 components、issue security、多 board、匿名存取。
  2. Team-managed（TMP）設定長在 project 裡、project admin 自己改；一個 board；沒有 components、issue security、匿名存取。
  3. TemplateScrum（sprint、backlog、velocity）vs Kanban（連續流、WIP）；也有 business、service 的 template。
  4. 建 CMP 要 Jira adminTMP 有 Create team-managed projects 全域權限的人就能建。
  5. Share settings with an existing project建 CMP 時直接沿用另一個 project 的所有 scheme；改一次全部跟著變。
  6. TMP 的設定不能共用每個 TMP 各自一份。

共用設定

Share settings with an existing project

優點限制
建立快、設定一致改任何 scheme 都會影響所有共用的 project
Jira admin 維護一份某個 project 想不一樣，要先另做一份 scheme
新 project 立刻有相同的 issue type、workflow、欄位、權限只適用 CMP；需要 Jira admin（建 CMP 本來就要）
  1. 建立Create project → 選 template → 選 Company-managed → 勾 Share settings with an existing project → 選來源 project。
  2. 之後兩個 project 指向相同 scheme；在 Project settings 會看到「shared by N projects」。

動手做

實作 Lab：建一個共用 WEB 設定的 space，看改一次兩邊變

約 25 分鐘Jira admin；Standard 以上（共用設定在 Free 不能用）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：比較 CMP 與 TMP 的設定頁，用 Share settings 建一個和 WEB 共用 scheme 的 space，親眼看到改一次 workflow、兩個 space 一起變。

這個 Lab 對應的考點

CMP 的設定是可共用的 scheme、由 Jira admin 管；TMP 的設定只屬於自己。Share settings with an existing project 讓新 CMP 沿用所有 scheme：建立快、一致，但改一次影響全部。Template（Scrum／Kanban）與管理方式（CMP／TMP）是兩個選擇。

準備

  • WEB 至少有一張 issue 在 To Do。

步驟

  1. 你應該看到：WEB 顯示 Company-managed，TEAM 顯示 Team-managed。
  2. 你應該看到：WEB 有 Components，Permissions 等頁面顯示的是 scheme 名稱；TEAM 有 Work types、Access，設定直接在 space 裡改，沒有 Components。
  3. 你應該看到：WEB 有 Backlog、可以 Create sprint；TEAM 是連續流的 board，通常沒有 sprint。Template 決定工作方式，跟 CMP／TMP 是兩回事。
  4. 你應該看到：Web Mobile 建好了（key 由 Jira 產生）。
  5. 你應該看到：和 WEB 是同一份（例如 WEB Permission Scheme）；頁面通常會提示這個設定被多個 space 共用。
  6. 你應該看到：儲存成功。官方說明：所有使用這個 workflow 的 space 都會一起更新。
  7. 你應該看到：兩邊都出現 Lab Check：改一次，共用的 space 一起變。
  8. 你應該看到：TEAM 的 workflow 只屬於 TEAM；建 team-managed space 時沒有共用設定可選。

試試看：改一個設定，觀察差異

T1用 Kim 的瀏覽器點 Create space，選一個 template，看能選哪一種管理方式（不要真的建立）。看結果
通常 Kim 只能建 team-managed：建 CMP 要 Jira admin；TMP 只要有 Create team-managed spaces 全域權限（預設一般使用者就有）。
T2（想像，不實際做）Web Mobile 想要自己的 workflow、不影響 WEB，該怎麼做？看結果
另做一份 workflow scheme（與 workflow），改好後把 Web Mobile 換成新 scheme。共用就是一起變；要不一樣，得先分家。
T3（想像，不實際做）團隊要固定兩週一個 sprint、看 velocity，又想自己改流程、不找 Jira admin。看結果
Scrum template＋Team-managed。先選管理方式，再選工作方式。
心像錨點：閉上眼睛想一次這個畫面

Create space 畫面上那個 Share settings with an existing space 勾選框，下面是 Choose space 下拉選單。勾下去，兩個 space 從此綁在同一份 scheme 上：一起快、一起變。

收尾

  • 在 workflow editor 刪掉 Lab Check（有 issue 在 Lab Check 就先移回原 status）→ Update workflow。
  • Web Mobile 是 Lab 自建的：側欄 Spaces 旁的 ••• → Manage spaces → 找到 Web Mobile，從它的 ••• 選單移到 trash（Jira admin 之後還能從 trash 還原）。Premium 以上的站台也可以改用 Archive（space 封存只有 Premium、Enterprise 有）。
