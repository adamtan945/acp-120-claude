動手做 Lab

Lab 環境準備

每一節最後都有一個「動手做 Lab」：照步驟在測試站台實際點一次，看到真的畫面、親手改一次設定，考題情境出現時腦中就有畫面。這一頁準備所有 Lab 共用的環境，只要做一次。

約 30 分鐘只在測試站台做

為什麼要動手

看過、點過、弄壞過，才記得住

  1. 看到畫面設定在哪一頁、按鈕叫什麼。考題問「在哪裡設定」時，腦中直接浮現那一頁。
  2. 親手改一次改完用另一個帳號看結果，記住「因 → 果」。
  3. 故意弄壞每個 Lab 都有「試試看」：拿掉一個權限、換一個設定，看會發生什麼。考題的錯誤選項通常就是這些情境。
  4. 留下心像錨點每個 Lab 最後有一句「閉上眼睛想一次這個畫面」，考前複習只要想這些畫面。
站台

用哪一種站台

方案能做的 Lab說明
Free◐ 部分沒有 permission scheme、project role、issue security scheme；project 不能公開；TMP 不能限制 issue type。120.1 大部分 Lab 做不了。
Standard◐ 幾乎全部除了 project 封存（archive 要 Premium 以上）都能做。
Premium（建議用試用）✓ 全部可以做全部 Lab；用 Atlassian 的免費試用開一個新站台最省事。
不要在公司正式站台做

Lab 會改 permission scheme、刪 group、把 project 設成公開、還原 backup。請用個人試用站台或公司專用的 sandbox。如果你在正式站台上，只做「看」的步驟。

  • 自己建立站台的人會是 org admin，也有 Jira 的 admin 權限，可以做全部 Lab。
  • 現行畫面把 project 叫做 space、issue 叫做 work item，⚙ Settings 底下的 Issues 叫做 Work items。考試仍用 project／issue。
測試帳號

三個人，用來切換視角

名字角色Group用途
你Org admin＋Jira admin—設定
Leo開發者team-leadsWEB 的 Developers role
Kim一般使用者—只看、不改；測試看不到的情境
AnaHRhr-teamIssue security 的 HR level
  1. 準備三個 email用 email 別名（例如 Gmail 的 你的帳號+leo@gmail.com）或其他信箱；每個 email 是一個獨立的 Atlassian 帳號。
  2. 邀請Atlassian Administration›Directory›Users›Invite users：輸入 email，Jira 的角色選 User。
  3. 接受邀請到各信箱點邀請信，設定名字（Leo、Kim、Ana）。
  4. 建 groupDirectory›Groups›Create group：建 team-leads（加 Leo）、hr-team（加 Ana）。
  5. 切換視角每個測試帳號用一個瀏覽器設定檔（Chrome profile）或另一個瀏覽器登入，就能同時開著你和 Leo 的畫面對照。無痕視窗用來當「未登入的路人」。
測試 project

兩個 project，CMP 與 TMP 各一

Key名稱類型建立方式
WEBWeb AppCompany-managed（Scrum）Create space → Scrum → 選 Company-managed
TEAMTeam BoardTeam-managed（Kanban）Create space → Kanban → 選 Team-managed
  • 在兩個 project 各建 5～10 張 issue（Story、Bug、Task 都要有，至少一張有 sub-task）。
  • WEB 的 permission scheme 先複製一份：⚙ Settings → Work items → Permission schemes → 預設 scheme 的 Copy，改名 WEB Permission Scheme，再到 WEB 的 Space settings → Permissions → Actions → Use a different scheme 換成它。之後的 Lab 都改這份，不動到預設 scheme。
  • WEB 的 Space settings → People（新介面可能叫 Access）：把 Leo 加進 Developers，Kim 與 Ana 加進 Users（沒有這兩個 role 就在 ⚙ Settings → System → Project roles 建立）。
  • 打開 WEB Permission Scheme 看一遍：如果有權限給了 Application access 或 Any logged in user，改成給對應的 role（Browse 給 Users、Developers、Administrators；編輯類給 Developers、Administrators）。這樣「誰在哪個 role」就決定一切，Lab 的結果才會跟步驟寫的一樣。
準備好了

之後每個 Lab 的「準備」只會寫這一頁以外需要的東西。Lab 做完都有「收尾」步驟，把設定改回來，下一個 Lab 才不會被影響。

小技巧

做 Lab 時

  • 先讀完該節教材再做 Lab；做 Lab 時遇到不懂的名詞，回到上面的段落看。
  • 步驟前的方框可以打勾，進度只存在這台裝置。
  • 畫面和文字對不上時，用頁面上方的搜尋或 ⚙ Settings 的搜尋框找設定名稱；Atlassian 常改選單位置，但設定名稱大多不變。
  • 權限改了沒生效？讓測試帳號重新整理頁面；必要時登出再登入。
