Issue type 與 issue type scheme

  1. Issue type 是全站物件Settings → Issues → Issue types；改名會影響所有使用它的 project。
  2. Issue type scheme決定一個 project 有哪些 issue type、順序與預設值；可多 project 共用。
  3. CMP 對應Issue type 透過 workflow scheme、issue type screen scheme、field configuration scheme 各自對應 workflow、screen、欄位行為。
  4. Sub-task全站開關（Settings → Issues → Sub-tasks）；sub-task 的工時可彙總到 parent（Include sub-tasks）。
  5. Epic跨 sprint 的大工作；CMP 的 epic 可以有其他 project 的 child（cross-project epic）。
  6. TMPProject admin 在 Project settings → Issue types 直接建，欄位拖拉加入。

動手做

實作 Lab：新增全站 work type，加進 WEB 的 scheme

約 25 分鐘Jira admin（CMP 的 work type）；TEAM 的 Administrator（TMP 部分）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：從全站建立一個 issue type，看它要加進 issue type scheme 才出現在 WEB；改名看全站生效；再在 TEAM 自建一個只屬於 TEAM 的 type。

這個 Lab 對應的考點

Issue type 是全站物件：建好要加進 issue type scheme 才會出現在 project；改名全站生效；從 scheme 移除使用中的 type 要先 migrate。CMP 的 issue type 透過三種 scheme 對應 workflow、screen、field configuration。TMP 的 issue type 由 project admin 自己建。

準備

  • WEB 有一張 Story，底下有 sub-task。

步驟

  1. 你應該看到：Work types 清單多了 Lab Request。
  2. 你應該看到：通常沒有 Lab Request：全站建好了，但還沒加進 WEB 用的 work type scheme。
  3. 你應該看到：WEB 的 Create 下拉選單出現 Lab Request。
  4. 你應該看到：看得到這個 type 用哪個 workflow、哪些畫面與欄位：都是 WEB 的 workflow scheme、issue type screen scheme、field configuration scheme 依 type 決定的（沒特別設定就落到 Default）。
  5. 你應該看到：剛建的 issue、搜尋結果、Create 下拉選單都變成 Lab Ticket：issue type 名稱是全站的，所有用它的 project 都會變。
  6. 你應該看到：Subtasks 是啟用的；要停用必須先把現有的 sub-task 轉成 standard type。
  7. 你應該看到：TEAM 多了自己的 Lab Request，跟全站的 Lab Ticket 無關。TMP 只能自建 standard type，不能自建 parent 或 subtask type。

試試看：改一個設定，觀察差異

T1在 Work type schemes 把 Lab Ticket 從 WEB 的 scheme 拖回 Available Work Types → Save。看結果
WEB 已有一張 Lab Ticket issue，所以 Jira 跳出 migration wizard，要你選新的 work type（例如 Task）、status 與欄位值，確認後才移除。可以先按取消，收尾時再做。
T2在 WEB 那張 Story 的 sub-task 記 1h 工時（Log time），打開 Story 的 time tracking，找「包含 sub-task」的選項（Include subtasks）。如果 issue 上沒有 time tracking，略過這題。看結果
勾選後 Story 顯示的時間包含 sub-task 的 1h；不勾只算自己。這就是 sub-task 工時彙總到 parent。
T3（想像，不實際做）WEB 的 Epic 想掛另一個 CMP 的 Story；WEB 的 Story 想掛另一個 project 的 sub-task。看結果
前者可以：CMP 的 epic 可以有其他 project 的 child（cross-project epic）。後者不行：sub-task 一定與 parent 同 project。
心像錨點：閉上眼睛想一次這個畫面

Work type schemes 的編輯頁：左邊 Available Work Types、右邊 Work Types for Current Scheme，把卡片拖過去。建 type 是全站，拖進 scheme 才到 project。

收尾

  • 把 WEB 的 Lab Ticket issue 改成 Task（或走 migration wizard），從 WEB 的 scheme 移除 Lab Ticket，再到 Work types 刪除 Lab Ticket（Lab 自建）。
  • TEAM：Space settings → Work types → Lab Request → •••（More actions）→ Delete work type。
