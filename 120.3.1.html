Issue type 與 issue type scheme

  1. Issue type 是全站物件Settings → Issues → Issue types；改名會影響所有使用它的 project。
  2. Issue type scheme決定一個 project 有哪些 issue type、順序與預設值；可多 project 共用。
  3. CMP 對應Issue type 透過 workflow scheme、issue type screen scheme、field configuration scheme 各自對應 workflow、screen、欄位行為。
  4. Sub-task全站開關（Settings → Issues → Sub-tasks）；sub-task 的工時可彙總到 parent（Include sub-tasks）。
  5. Epic跨 sprint 的大工作；CMP 的 epic 可以有其他 project 的 child（cross-project epic）。
  6. TMPProject admin 在 Project settings → Issue types 直接建，欄位拖拉加入。

Sub-task 與 epic

什麼時候用

Sub-taskEpic
用途把一張 issue 拆給多人或多步驟跨 sprint 的大目標，下面掛 story、task、bug
階層Standard issue 的 childStandard issue 的 parent
Sprint跟 parent 一起不進 sprint
跨 project✗ 與 parent 同 project✓ CMP 的 epic 可有其他 project 的 child
工時可彙總到 parent（勾 Include sub-tasks）看 epic 的整體進度
  • 啟用／停用 sub-tasks：Settings → Issues → Sub-tasks（全站）；有 sub-task 存在時要先轉成 standard type 才能停用。
  • Time tracking 彙總：parent 的 time tracking 可以把 child（sub-task）的 original、remaining、logged 一起算進來（Include sub-tasks）；官方：child 超過 100 個時無法納入彙總。
本段必考
  • Sub-task 工時可彙總到 parent。
  • Cross-project epic 只在 CMP。
