Fields

Custom field 的三個開關：context 決定在哪、screen 決定在不在畫面、field configuration 決定行為。考你建立、設定與排查。

3 分鐘速覽

Custom field、context、field configuration

  1. Custom field 是全站物件Jira admin 建立；選類型、名稱、context、要放上哪些 screen。
  2. Context決定欄位在哪些 project 與 issue type 出現、預設值、選項；同一個 project 只能屬於一個 context。
  3. Field configuration決定欄位行為：description、Required、Hidden、renderer（wiki 或純文字）、可用的 screen。
  4. Field configuration scheme依 issue type 套用不同 field configuration。
  5. 欄位沒出現？查三件事：context（project／issue type）、screen 上有沒有、field configuration 有沒有 hide。
  6. TMPProject admin 在 issue type 上拖拉欄位；建的欄位只在該 project。

建立

建立 custom field

  1. 類型Settings → Issues → Custom fields → Create custom field → 選類型（text、number、select、multi-select、user picker、date、checkbox、cascading select…）。
  2. 名稱與說明命名；同名欄位會讓 JQL 與管理混淆。
  3. Context預設是 global（所有 project、所有 issue type）；可改成特定 project 與 issue type，並設預設值與選項。
  4. Screens選要放上哪些 screen；沒放上 screen 就看不到也填不了。
Context 設定說明
Applicable issue types哪些 issue type 有這個欄位
Applicable projectsGlobal 或指定 project；一個 project 只能在一個 context
Default value每個 context 各自的預設值
Options（select 類）每個 context 各自的選項清單
考題長相

「同一個 Severity 欄位，A project 的選項是 S1–S4，B project 是 Low／High」→ 建兩個 context，各自設選項。不需要建兩個欄位。

本段必考
  • 不同 project 要不同選項 → 多個 context。

Field configuration

欄位行為

設定效果
Required建立、編輯時必填（任何畫面都檢查）
Hide在使用此 field configuration 的 issue 上完全隱藏（即使 screen 有）
RendererWiki style（可格式化）或 Default text（純文字）
Description欄位下方的說明文字
Screens看這個欄位在哪些 screen 上
  1. 建立Settings → Issues → Field configurations → Add（或複製 Default）。
  2. 對應 issue typeField configuration schemes → 新增 scheme → Associate an issue type with a field configuration。
  3. 套到 projectProject settings → Fields → 選 field configuration scheme。

TMP 欄位

Team-managed 的欄位

  • Project settings → Issue types → 選 type → 從右側拖拉欄位（或 Create field）。
  • 在 TMP 建的欄位只屬於這個 project，不能被其他 project 使用。
  • 可用欄位類型：short text、paragraph、date、number、dropdown、checkbox、label、people、time stamp 等。
本段必考
  • TMP 欄位不共用。

動手做

實作 Lab：Lab Severity：context、必填、隱藏

約 30 分鐘Jira admin；TEAM 的 Administrator（TMP 欄位）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：建一個全站 select 欄位，用 context 控制它出現在哪、用 field configuration 控制必填與隱藏；再在 TEAM 建一個只屬於 TEAM 的同名欄位。

這個 Lab 對應的考點

Custom field 三個開關：context 決定在哪些 project／issue type 出現與選項（一個 project 只能在一個 context）；screen 決定在不在畫面；field configuration 決定 required、hide、renderer。依 issue type 不同行為用 field configuration scheme。TMP 欄位只屬於該 project。

準備

  • 站台若已換成新的 Field schemes（Atlassian 正逐步用它取代 field configuration 與 field configuration scheme），步驟 5～7 的畫面會不同，照概念找對應設定。

步驟

  1. 你應該看到：Fields 清單出現 Lab Severity；它有一個預設 context：所有 project、所有 work type。
  2. 你應該看到：兩種都看得到 Lab Severity，選項 S1～S4。
  3. 你應該看到：Story 的 Create 視窗沒有 Lab Severity 了；Bug 仍有。Context 決定欄位出現在哪裡。
  4. 你應該看到：WEB 的 Bug 通常改用這個 context：選項變成 Low／High、預設 High。同一個欄位，不同 context 各有選項，不必另建同名欄位。
  5. 你應該看到：WEB 的 Bug 用 WEB Bug FC，其他 work type 走 scheme 裡的 Default。
  6. 你應該看到：兩次都被擋：required 在建立與編輯都檢查。
  7. 你應該看到：Lab Severity 不見了，即使它還在 screen 上：hide 比 screen 優先。
  8. 你應該看到：TEAM 的 Bug 有自己的 Lab Severity；它只屬於 TEAM，WEB 用不到，也不會跟全站那個混在一起。

試試看：改一個設定，觀察差異

T1在 Lab Severity 再新增一個 context，project 也選 WEB。看結果
選不到 WEB 或無法儲存：同一個欄位，一個 project 只能屬於一個 context。
T2在 WEB Bug FC 編輯 Description 那一列，把 Wiki renderer 關掉（只允許純文字），再編輯一張 Bug 的 description。看結果
通常只能輸入純文字、沒有格式工具；Story 不受影響。Text 欄位預設用 Wiki renderer。
T3刪除全站的 Lab Severity（Fields → ••• → Delete），再到 Deleted fields 分頁 → ••• → Restore。看結果
刪除不會立刻永久消失：先標記、60 天後才刪；期間 restore 會把欄位放回原本用到的地方，資料也回來。只在 Lab 自建的欄位上試。
心像錨點：閉上眼睛想一次這個畫面

Lab Severity 的 Contexts and default value 頁：兩張 context 卡片，一張寫全站、一張寫 WEB。在哪（context）、在不在（screen）、藏不藏（field configuration）。

收尾

  • WEB 的 Space settings → Fields 換回原本的 field configuration scheme；刪除 WEB FC Scheme 與 WEB Bug FC。
  • 刪除全站的 Lab Severity（Lab 自建，會先進 Deleted fields 60 天）。
  • TEAM：Space settings → Fields → Lab Severity 的 ••• → Remove field。
