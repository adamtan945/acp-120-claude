3 分鐘速覽

Automation：trigger → condition → action，加 branch

  1. ScopeProject rule（project admin 可建）vs global／multi-project rule（Jira admin）。
  2. Trigger只能一個：created、transitioned、field value changed、scheduled、manual…
  3. ConditionIssue fields、JQL、user、related issues、{{smart values}}、If/else。
  4. Branch對 related issues（sub-tasks、parent、linked、JQL 結果）各跑一次。
  5. Smart values{{issue.summary}}、{{issue.parent.key}}、{{now.plusDays(1)}}、{{triggerIssue}}。
  6. Actor 與權限Rule 以 actor（預設 Automation for Jira）執行；actor 要有 project 權限，rule 才改得動 issue。
資料來源（5）有疑慮時點開看官方原文
  • What are flow details and settings?To manage automation flows across an entire Jira or Confluence instance, you must be a Jira or Confluence app admin.
  • Jira automation triggersTriggers will listen for events in Jira, such as when a work item is created or when a field value is changed.
  • Jira automation conditionsIf a condition fails, no actions following it will be performed.
  • Jira automation branchesRelated issues branches allow you to perform actions on issues related to the issue that triggered the flow.
  • What is a flow actor?Any changes performed by an automation flow are seen as being performed by the flow actor.

Scope 與權限

Project rule vs global rule

Project ruleGlobal／multi-project rule
誰能建Project admin（Administer＋Browse Projects；可被 Jira admin 關閉）Jira admin（Administer Jira；任何 scope）
範圍單一 project多個 project、project type、全站
欄位、status這個 project 的所有 scope 內 project 都要一致
Usage（現行）以 automation step 計：trigger、condition、action、branch、loop 每執行一次算一步同左；額度在 organization 層級共用
  • Rule 的變更以 actor 名義執行（預設 Automation for Jira；可改成某個使用者）；actor 缺權限（例如 Transition、Edit、Browse）時，audit log 會顯示錯誤。
  • 誰能建 rule：CMP 要 Administer Projects＋Browse Projects；TMP 要 Administrator；Jira admin 可在 Global automation → Global configuration 關掉 project admin 管理 rule 的能力。
  • Permission scheme 收緊後 rule 失敗：檢查 actor 是否仍有該 project 的對應權限（推論：官方未列出 actor 的權限來源細節）。
  • Allow rule trigger：允許此 rule 被其他 rule 的動作觸發（避免無限迴圈預設關閉）。
本段必考
  • Actor 沒權限 → rule 失敗。
  • Global rule 要 Jira admin。

動手做

實作 Lab：Story 完成就關 sub-task，再拿掉 actor 的權限

約 30 分鐘WEB 的 project admin（建 project rule）；Jira admin（把 actor 設成別人、global automation）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：建一條 project rule：Story 轉 Done 時用 branch 把 sub-task 也轉 Done 並留言；再把 actor 換成 Leo、拿掉他的權限，看 rule 失敗。

這個 Lab 對應的考點

Rule＝一個 trigger＋condition＋branch＋action；改相關 issue 要用 branch；branch 裡用 {{triggerIssue}} 取原 issue。Project rule 由 project admin 建，multi-project 與 global 要 Jira admin。Rule 以 actor 身分執行，actor 缺權限 rule 就失敗。

準備

  • WEB 有一張 Story，底下 2 張 To Do 的 sub-task。
  • 120.4.1 的 Subtask Blocking Condition 已移除。
  • 每次執行會計入方案的 automation 用量；Lab 只跑幾次沒關係。

步驟

  1. 你應該看到：流程鏈最上面是 trigger；一條 rule 只能有一個 trigger。
  2. 你應該看到：Trigger 下面多了 condition：不是 Story 就停。
  3. 你應該看到：Branch 內縮顯示，底下兩個 action。
  4. 你應該看到：Rule 啟用；Scope 是 WEB 這個 space。
  5. 你應該看到：兩張 sub-task 都是 Done，留言寫著 parent 的 key 與你的名字；History 顯示由 Automation for Jira 轉換；audit log 的 Status 是成功。
  6. 你應該看到：Sub-task 沒被轉換；audit log 通常顯示錯誤或部分失敗：rule 以 Leo 的身分執行，Leo 沒有 Transition 權限。
  7. 你應該看到：Sub-task 轉成 Done，History 顯示是 Leo 做的。
  8. 你應該看到：Global automation 列出各 space 的 rule；Global configuration 有 Allow space administrators to manage space flows。

試試看：改一個設定，觀察差異

T1用 Leo（暫時加進 WEB 的 Administrators role）打開 WEB 的 Automation，建一條新 rule，看 Flow details 的 Scope。看結果
Leo 能建 WEB 的 rule，但 scope 只能是這個 space；multi-space 與 global 只有 Jira admin 能設。
T2在 Global configuration 取消 Allow space administrators to manage space flows，再用 Leo 打開 WEB 的 Automation。看結果
Leo 不能再建立或管理 rule。這是全站設定，做完立刻勾回去。
T3在 LAB close subtasks 的 condition 後面加 If/else block：Priority equals Highest 時對 Story 留言「高優先已完成」，else 留言「一般優先已完成」。分別用 Highest 與 Medium 的 Story 測。看結果
兩張 Story 各得到不同的留言，後面的 branch 照常執行：if/else 是分流，不是擋下。
心像錨點：閉上眼睛想一次這個畫面

Rule 編輯器的流程鏈：Work item transitioned → Issue fields condition → Sub-tasks branch 內縮兩個 action；Flow details 裡寫著 Actor。觸、條、枝、動；actor 要有權。

收尾

  • Rule 的 Actor 改回 Automation for Jira，然後關閉或刪除 LAB close subtasks。
  • 確認 WEB Permission Scheme 的 Transition Issues 已加回 Developers；Global configuration 的勾選已恢復。
  • Leo 移出 WEB 的 Administrators role。
