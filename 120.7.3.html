Status、resolution、priority

3 分鐘速覽

Status、resolution、priority 都是全站物件

  1. 建立Settings → Issues → Statuses／Resolutions／Priorities（Jira admin）。
  2. 改名影響全站CMP 的 status、resolution、priority 改名，所有使用它的 project、filter、board 都看到新名稱。
  3. TMP status屬於該 project，改名只影響自己。
  4. Resolution可設 default；有值＝已解決；不要放 create screen。
  5. Priority scheme不同 project 可以用不同 priority 清單。
  6. 停用 sub-tasksSettings → Issues → Sub-tasks；有 sub-task 存在時要先轉成 standard type。

改名前想清楚

改名後所有 project 的使用者都會看到新名稱；用到舊名稱的 filter 與 JQL 記得檢查。只想某個 project 不同 → 建新的 status 或 priority scheme。

Sub-tasks 與 TMP

停用 sub-tasks、TMP status

  • 停用 sub-tasks：全站開關；已有 sub-task 時，要先把它們轉成 standard issue type。停用後無法建立 sub-task。
  • TMP 的 status：每個 TMP 有自己的 status，改名、刪除只影響這個 project；不會影響其他 TMP 或 CMP。
  • Priority scheme：Settings → Issues → Priority schemes：替不同 project 指定不同的 priority 清單與預設值。
本段必考
  • TMP status 改名只影響自己。

動手做

實作 Lab：改一個 status 名稱，看誰跟著變

約 30 分鐘Jira admin（TEAM 的部分要 TEAM 的 space admin）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：在全站把 WEB 用的 status 改名、加一個 resolution、做一個 priority scheme，再對照 TEAM 改 status 名稱只影響自己；最後看停用 sub-tasks 的前提。

這個 Lab 對應的考點

CMP 的 status、resolution、priority 是全站物件，改名所有用到的 project 都看到；TMP 的 status 只屬於該 project；priority scheme 讓不同 project 用不同清單；停用 sub-tasks 前要先把既有 sub-task 轉成 standard type。

準備

  • WEB 至少有一張 In Progress 的 issue；TEAM 也有一張 In Progress。
  • WEB 至少有一張帶 sub-task 的 issue（環境頁已準備）。

步驟

  1. 你應該看到：這個 status 是全站共用的物件；頁面通常會看得出它被哪些 workflow 使用。
  2. 你應該看到：WEB 的 board 欄位與 issue 狀態都顯示 Doing；任何用到這個 status 的 company-managed space 都一樣。
  3. 你應該看到：TEAM 通常仍顯示 In Progress（TMP 的 status 是它自己的）。再看 Lab IP 的 JQL 與結果：記下改名對既有 filter 的影響（官方文件沒有說明，以你看到的為準）。
  4. 你應該看到：只有 TEAM 變成 Doing，WEB 不受影響：TMP 改 status 名稱只影響自己。
  5. 你應該看到：Resolution 清單出現 Lab Won't do，所有 project 共用。頁面上也看得到哪一個是 default。
  6. 你應該看到：WEB 的 priority 下拉只剩 High、Medium、Low：不同 project 可以用不同 priority 清單。
  7. 你應該看到：WEB 已經有 sub-task，所以要先把它們轉成 standard work type 才能停用；畫面若要你轉換，到這裡就停。

試試看：改一個設定，觀察差異

T1刪除 Lab Won't do（收尾時本來就要刪）。看結果
沒有 issue 用到時會直接刪除。有 issue 用到時的處理方式 Cloud 文件沒寫，照畫面提示做並記下來。
T2（想像，不實際做）只想讓 WEB 的 In Progress 叫 Doing，其他 project 不變。看結果
不能直接改名：改名是全站的。要建一個新的 status Doing，放進 WEB 的 workflow。
T3（想像，不實際做）WEB 有 sub-task 時直接停用 sub-tasks。看結果
做不到：要先把既有 sub-task 轉成 standard work type。停用後無法再建立 sub-task。
心像錨點：閉上眼睛想一次這個畫面

Statuses 頁上一列 In Progress，改名成 Doing 的那一刻，WEB 的 board 跟著變，TEAM 的 board 紋風不動。狀、解、優都全站，TMP 例外。

收尾

  • TEAM 的 Doing 改回 In Progress；確認全站的 In Progress 名稱正確。
  • 刪除 Lab Won't do 與 Lab IP filter。
  • WEB 改回原本的 priority scheme，再刪除 WEB priorities。
