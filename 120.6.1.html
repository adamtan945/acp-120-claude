3 分鐘速覽

JQL：field、operator、value、keyword、function

  1. 結構field operator value，用 AND、OR、NOT 連接，ORDER BY 排序；括號決定優先順序。
  2. Custom field用名稱（"Story Points"）或 cf[10010]；名稱有空白要加引號。
  3. 常用 operator=、!=、IN、NOT IN、~（文字包含）、IS EMPTY、WAS、CHANGED、>、<。
  4. 常用 functioncurrentUser()、membersOf()、startOfWeek()、endOfMonth()、now()、openSprints()、releasedVersions()、linkedIssues()。
  5. 日期created >= -7d、resolved >= startOfMonth()、duedate < now() AND resolution = Unresolved。
  6. Basic search 的限制不能用 OR 組合不同欄位、不能用括號、不能用 WAS／CHANGED 等歷史查詢。

括號很重要

project = WEB AND priority = High OR labels = urgent 會變成「(WEB 且 High) 或 任何 project 的 urgent」。要限定 WEB 就寫 project = WEB AND (priority = High OR labels = urgent)。

優先序：官方文件寫「沒有括號時由左到右計算」；社群常見的說法則是 AND 先於 OR。兩種說法對「A AND B OR C」結果相同，對「A OR B AND C」就不同，所以只要有 OR 就加括號，考題也選加括號的寫法。

動手做

實作 Lab：括號、WAS 與 CHANGED：同一題寫兩種 JQL

約 25 分鐘任何使用者（能 Browse WEB、TEAM）

第一次做 Lab？先看 Lab 環境準備：用測試站台、準備測試帳號。畫面名稱可能隨 Atlassian 更新而不同，以下以現行畫面為準。

目標：先用 basic search 卡住，再切到 JQL，親眼看括號、WAS／CHANGED、日期 function、currentUser() 造成的結果差異。

這個 Lab 對應的考點

官方：沒有括號時由左到右計算，有 OR 就用括號控制；WAS 含建立時的值、CHANGED 只找改過的；未解決用 resolution = Unresolved；basic search 不能跨欄位 OR、不能括號、不能歷史查詢。

準備

  • WEB 的 issue A：把 priority 從 Medium 改成 High。
  • WEB 的 issue B：priority Low、label urgent。TEAM 的 issue C：label urgent。
  • WEB 的 issue D：未解決，due date 設成昨天。
  • WEB 有 2 張指派給你、2 張指派給 Leo 的未解決 issue。

步驟

  1. 你應該看到：做不到：basic 的各個下拉選單之間一律是 AND，不能跨欄位 OR，也沒有括號。
  2. 你應該看到：Basic 選好的條件自動變成一行 JQL，例如 project = WEB。
  3. 你應該看到：結果裡出現 TEAM 的 C：這句等於「(WEB 且 High) 或 任何 space 的 urgent」（官方：沒有括號時由左到右計算）。
  4. 你應該看到：C 不見了，只剩 WEB 的 A、B。切回 basic 通常會被擋下或提示查詢太複雜。
  5. 你應該看到：CHANGED 只找到 A；WAS 找到 A，加上所有現在或建立時就是 Medium 的 issue（WAS 含建立時的值）。
  6. 你應該看到：第一句找到 D（過期未解決）。第二句是「上個月建立的」；新站台通常是空的，這正是它沒有算到本月。
  7. 你應該看到：自動完成列出含 Story 的欄位；名稱有空白的 custom field 要加引號，也可以用 cf[ID] 寫法（ID 依站台而不同）。
  8. 你應該看到：同一個網址，你看到指派給你的 2 張，Leo 看到指派給 Leo 的 2 張：currentUser() 依執行的人計算。

試試看：改一個設定，觀察差異

T1執行 project = WEB AND status = Done AND resolution = Unresolved。看結果
有結果就代表「status 是 Done 但 resolution 是空的」：已解決要看 resolution，不是看 status 名稱。沒有結果也只代表這個 workflow 剛好有設 resolution。
T2執行 assignee IN membersOf("team-leads")，再把 Leo 移出 team-leads 後重跑。看結果
第一次找到指派給 Leo 的 issue；Leo 移出後結果變空。做完把 Leo 加回 team-leads。
T3把步驟 5 改成 priority WAS High DURING (-30d, now())。看結果
找到過去 30 天內曾經是 High 的 issue（A 在內）。DURING 是 WAS／CHANGED 才能用的歷史條件。
心像錨點：閉上眼睛想一次這個畫面

JQL 框裡同一句話，加上一對括號，TEAM 的 C 就從結果裡消失。有 OR 就加括號。

收尾

  • Leo 在 team-leads；A、B、C、D 可以留著，120.6.2 與 120.6.3 還會用到指派給你和 Leo 的 issue。
